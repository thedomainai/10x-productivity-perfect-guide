# Phase 4: Workflow Design（ワークフロー設計）

## 到達状態

> 業務タスクの種類に応じて Claude Code を最適に活用できる。
> AI が日常業務のあらゆる場面で Second Brain として機能している。

## なぜワークフロー設計が必要か

Phase 1-3 で AI の「基本操作」「文脈供給」「能力拡張」を学んだ。
しかし、**実際の業務にどう組み込むか**を設計しないと、以下の問題が起きる:

- AI を使うべき場面で使い忘れる
- AI を使うこと自体が追加の手間になる

ワークフロー設計のゴールは**「AI を使うことを意識しなくなる」こと**。
呼吸のように自然に AI を業務に組み込む。

## 4-1. ビジネスタスクの分類と Claude Code の活用

### タスクの分類

```
ビジネスタスク
├── 情報収集系（インプット）
│   ├── 市場・競合リサーチ
│   ├── 社内資料の検索・要約
│   ├── 技術調査・トレンド把握
│   └── 顧客フィードバックの分析
├── 思考支援系（プロセス）
│   ├── 論点の整理・構造化
│   ├── 選択肢の比較・トレードオフ分析
│   ├── 仮説の構築・検証計画
│   └── 意思決定の壁打ち
├── 生成系（アウトプット）
│   ├── 報告書・提案書の作成
│   ├── メール・メッセージの作成
│   ├── プレゼン資料のドラフト
│   └── 議事録の整理
├── 管理系（マネジメント）
│   ├── タスクの優先度整理
│   ├── 進捗の可視化
│   ├── リスクの洗い出し
│   └── スケジュール管理
└── 開発系（エンジニアリング ※応用）
    ├── コーディング・テスト
    ├── コードレビュー
    ├── リファクタリング
    └── デプロイ・CI/CD
```

### Claude Code の活用パターン

| タスクの種類 | Claude Code での指示例 |
|-------------|----------------------|
| **調査・リサーチ** | `/research AI市場動向` |
| **文書作成** | `提案書のドラフトを作って` |
| **ファイルの修正・改善** | `report.md をもっと簡潔にして` |
| **複数ファイルの横断的な調査** | `docs/ 内のファイルを分析して` |
| **定型業務の実行** | `/weekly-report` |
| **壁打ち・ブレスト** | `新規事業の方向性で相談したい` |
| **大量のファイルの一括処理** | `全ファイルのフォーマットを統一して` |

## 4-2. ワークフローパターン

### パターン A: 調査→判断

**場面**: 新しい施策の検討、意思決定に必要な情報収集

```
1. Claude Code に /research でトピックを調査させる
2. AI がレポートを作成（論点整理、選択肢の比較表つき）
3. Cursor でレポートを開き、内容を確認
4. Claude Code に不明点を深掘りさせる
5. レポートに自分の判断を追記して意思決定を記録
6. Memory に判断の理由を蓄積
```

**認知負荷の変化:**
```
従来:  自分で調べる(60分) → 整理する(30分) → 判断する(10分)
AI活用: AIに調べさせる(5分) → 結果を確認(10分) → 判断する(10分)
       ※調査中は別の仕事ができる
```

### パターン B: ドラフト→レビュー→仕上げ

**場面**: 報告書、提案書、メールなどの文書作成

```
1. Claude Code に文書のドラフトを作成させる
   「requirements.md をもとに提案書のドラフトを作って」
2. Cursor でドラフトを開き、内容を確認
3. Claude Code に修正指示を出す
   「proposal.md の第2段落をもっと具体的な数値で裏付けて」
4. 最終確認して完成
```

**認知負荷の変化:**
```
従来:  構成を考える(20分) → ゼロから書く(60分) → 推敲(20分)
AI活用: 要件を伝える(5分) → ドラフト確認(15分) → 微調整(10分)
```

### パターン C: 会議の前後

**場面**: 会議の準備と後処理

```
会議前:
1. Claude Code に /meeting-prep で会議資料を準備させる
   「agenda.md の議題について論点と想定質問を整理して」
2. Cursor で資料を確認、必要に応じて Claude Code に修正を依頼

会議後:
3. 議事録メモを Claude Code に渡す
   「この議事録からアクションアイテムを抽出して、担当者と期限を整理して」
4. Memory に決定事項を記録
```

### パターン D: 壁打ち→構造化

**場面**: 曖昧な課題をクリアにしたい、アイデアを整理したい

```
1. Claude Code に相談する
   「新規事業の方向性で悩んでいる。A案とB案があるんだけど...」
2. AI が論点を整理し、比較表を提案
3. 対話を通じて思考が整理される
4. Claude Code に「今の議論をもとに比較分析レポートを作って」
5. 構造化された文書として保存
```

### パターン E: バックグラウンド並行処理

**場面**: 複数の独立したタスクを同時に進めたい

```
┌─ ターミナル 1 ──────────────────────────┐
│ Claude Code: 提案書のドラフト作成中       │
└────────────────────────────────────────┘

┌─ ターミナル 2 ──────────────────────────┐
│ Claude Code: 競合分析リサーチ実行中       │
└────────────────────────────────────────┘

→ 人間: Cursor でファイルを確認しながら待つ、または別の仕事に集中
```

Cursor のターミナルは複数開けるため、Claude Code を複数インスタンス同時に実行できる。

## 4-3. 判断フローチャート

タスクが来たとき、どう Claude Code を使うかの判断:

```
タスクが来た
│
├─ 定型業務（毎週やる作業等）→ /skill-name で Skill 呼び出し
│
├─ 調査・リサーチ → Claude Code に /research で依頼
│
├─ 文書の新規作成 → Claude Code にドラフト作成を依頼
│
├─ 既存ファイルの修正 → Claude Code にファイルを指定して修正指示
│
├─ 壁打ち・相談 → Claude Code と対話形式で議論
│
└─ 複数タスクの同時処理 → ターミナルを複数開いて並列実行
```

## 4-4. 応用例

Second Brain のフレームワークは、業務領域に応じて CLAUDE.md と Skills を追加するだけで応用できる。以下は代表的な応用パターン。

### 営業・事業開発

CLAUDE.md に追加する情報: ターゲット顧客像、商談プロセス、競合情報、価格体系
よく使う Skills: 顧客リサーチ、提案書ドラフト、競合比較表、商談議事録整理

### プロジェクトマネジメント

CLAUDE.md に追加する情報: プロジェクト計画、マイルストーン、リスク一覧、ステークホルダー
よく使う Skills: 進捗レポート、リスク分析、会議アジェンダ作成、議事録整理

### ソフトウェア開発

CLAUDE.md に追加する情報: 技術スタック、コーディング規約、ビルド・テストコマンド
Rules に追加: 言語固有のコーディングルール
よく使う Skills: コードレビュー、テスト実行→修正ループ、リファクタリング

**ポイント**: どの領域でも「Phase 2-3 で構築した Second Brain に、その領域の文脈を追加する」だけ。特別な設定は不要。

## 4-5. チームでの運用

### チームで共有すべき設定

| ファイル | Git 管理 | 理由 |
|---------|---------|------|
| `CLAUDE.md`（プロジェクト） | する | プロジェクト文脈はチーム共通 |
| `.claude/rules/` | する | プロジェクト固有のルール |
| `.claude/skills/` | する | プロジェクト共通の Skills |
| `~/.claude/CLAUDE.md` | しない | 個人の役割・好みは個人設定 |
| `~/.claude/skills/` | しない | 個人のワークフローは個人設定 |

### チームでの推奨ルール

1. **プロジェクトの CLAUDE.md は全員が参照・更新する**
2. **個人の preset は各自がカスタマイズする**
3. **AI が生成した成果物も通常のレビュープロセスを通す**
4. **有用な Skill はチームで共有する**

## 4-6. 実践: ワークフローの確立

### 演習 1: 1 日の業務を AI で支援する

1. 明日の業務タスクを 5 つ書き出す
2. 各タスクに「Claude Code でどう指示するか」を割り当てる
3. 実際にそのパターンで 1 日を過ごす
4. 振り返り: どのタスクで AI が最も効果的だったか

### 演習 2: ワークフローパターンの実践

1. パターン A-E から 2 つ以上を選んで実践する
2. 各パターンの「認知負荷の変化」を体感する
3. 自分の業務に最もフィットするパターンを特定する

### 演習 3: 並行処理の実践

1. 独立した 2 つのタスクを用意する
2. Cursor のターミナルを 2 つ開き、それぞれで Claude Code を起動して同時に進行する
3. 両方の結果を確認し、並行処理の効果を評価する
